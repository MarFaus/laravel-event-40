# Практическая работа «Получение и отображение мероприятий через API»: ответы

Все примеры взяты из проекта «Антракт»: маршруты в `routes/api.php`, контроллер
`app/Http/Controllers/Api/EventController.php`, страница `/events-api`,
скрипты `public/js/events-api.js` и `events-catalog-api.js`.

## Задание: почему контроллер возвращает JSON, а не HTML

API обслуживает не только эту страницу, но и любых других клиентов: мобильное
приложение, другой сайт, скрипт. Им не нужна разметка, им нужны данные.
JSON не содержит вёрстки, его легко разбирает любой язык, он компактнее HTML,
а интерфейс сам решает, как показать название, цену и статус.

## Контрольные вопросы

**1. Что такое API и для чего оно используется в Laravel?**
API (Application Programming Interface) — интерфейс, через который одна часть
приложения или другое приложение запрашивает данные и операции. В Laravel
через API браузер, мобильное приложение или внешний сервис получают данные
мероприятий, не загружая страницу целиком. В проекте это `GET /api/events`.

**2. Чем отличаются `routes/web.php` и `routes/api.php`?**
`web.php` — маршруты страниц: к ним подключаются сессии, cookie и защита от CSRF,
ответом обычно служит HTML. `api.php` — маршруты для данных: без сессий, ко всем
адресам автоматически добавляется префикс `/api`, ответом обычно служит JSON.
В проекте `api.php` подключён в `bootstrap/app.php` строкой `api: __DIR__.'/../routes/api.php'`.

**3. Что такое JSON?**
Текстовый формат обмена данными. Он состоит из объектов `{}`, массивов `[]`,
строк, чисел, `true`, `false` и `null`. Его понимают JavaScript, Laravel,
мобильные приложения и другие системы.

**4. Для чего используется `response()->json()`?**
Преобразует массив или коллекцию PHP в JSON, ставит заголовок
`Content-Type: application/json` и код ответа (по умолчанию 200, можно указать
другой, например 500 или 422). Клиент сразу понимает, что получил JSON.

**5. Какую задачу выполняет `fetch()`?**
Отправляет HTTP-запрос из браузера и возвращает промис с ответом сервера.
Страница не перезагружается: данные запрашиваются и показываются на лету.

**6. Для чего нужны `response.json()` и `response.ok`?**
`response.json()` читает тело ответа и превращает JSON в обычный объект или
массив JavaScript. `response.ok` равно `true` для кодов 200–299. `fetch()` не
считает ответы 404 и 500 ошибкой сам, поэтому код должен проверять `response.ok`
и сам выбрасывать ошибку, иначе скрипт попытается разобрать страницу ошибки как данные.

**7. Чем отличаются `async/await` и цепочка `.then()`?**
Оба способа работают с промисами. В цепочке `.then()` логика разбита на функции-обратные
вызовы, а ошибки ловит `.catch()`. В `async/await` код читается сверху вниз как
синхронный: `await` ждёт результат, ошибки обрабатываются обычным `try/catch`,
а `finally` выполняется в любом случае. В проекте использован `async/await`:
`finally` возвращает кнопке активное состояние и после успеха, и после ошибки.

**8. Как динамически создать HTML-карточку из полученных данных?**
Создать элементы через `document.createElement()`, записать текст через `textContent`,
добавить классы и вложить их друг в друга через `append()`. Готовую карточку
добавляют в контейнер. Так сделана функция `createCard()` в `events-api.js`.
Данные сервера не вставляют через `innerHTML`, чтобы разметка в названии
мероприятия не выполнилась как код.

**9. Почему необходимо обрабатывать ошибки API?**
Сервер может не ответить, вернуть 500, 404 или 422, сеть может пропасть. Без обработки
пользователь увидит пустую страницу и не поймёт причину. Нужно показать понятное
сообщение, вернуть кнопку в рабочее состояние и дать повторить запрос.
Страница `/events-api` показывает загрузку, успех, пустой список и ошибку с кодом.

**10. Зачем ограничивать количество возвращаемых записей?**
Большой ответ дольше передаётся, нагружает базу, сервер и браузер, а пользователю
всё равно не нужны тысячи записей сразу. Поэтому применяют `limit` и пагинацию.
В проекте `/api/events/catalog` по умолчанию отдаёт до 20 записей, максимум 50
на страницу, а режим `all=1` ограничен 1000 записей. Кнопка «Сравнить» на
странице показывает разницу в размере и времени.

**11. Чем отличается получение данных из API от непосредственного вывода данных в Blade?**
В Blade сервер формирует готовый HTML и отправляет страницу целиком: просто, хорошо
для поисковиков и работает без JavaScript, но обновление требует перезагрузки.
Через API сервер отдаёт только данные, а JavaScript обновляет часть страницы:
интерфейс отзывчивее, одни и те же данные можно использовать на сайте и в
мобильном приложении, но нужен JavaScript и отдельная обработка загрузки и ошибок.

**12. Какие операции должны проверяться на сервере при продаже электронных билетов?**
Всё, что влияет на деньги и доступ: существует ли мероприятие и не прошло ли оно,
остались ли билеты, допустимо ли количество, корректны ли имя и почта, итоговая
стоимость (её считает сервер по цене из базы, а не берёт из браузера), права
пользователя и защита от повторной отправки и одновременной покупки последних
билетов. В проекте это `EventController@order`: валидация, транзакция,
`lockForUpdate`, проверка остатка и даты. JavaScript может только показать цену.
