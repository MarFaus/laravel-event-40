# Ответы на контрольные вопросы

**1. Как взаимодействуют Laravel, Blade и JavaScript?**

Маршрут Laravel принимает запрос и передаёт его контроллеру. Контроллер получает
данные (из массива, модели или базы данных) и передаёт их в представление. Blade
формирует готовый HTML и отдаёт его браузеру. JavaScript работает уже с этим
HTML: реагирует на действия пользователя, изменяет интерфейс и при необходимости
отправляет новые запросы к Laravel. Распределение обязанностей такое: JavaScript
управляет интерфейсом, Laravel обрабатывает запросы и бизнес-логику, база данных
хранит информацию.

**2. В какой папке Laravel можно хранить публичные JavaScript-файлы?**

В папке `public`, обычно в `public/js`. Этот каталог доступен из браузера напрямую.
В проекте файлы лежат в `public/js/events.js` и `public/js/events-db.js`.
Второй способ — `resources/js` со сборкой через Vite; тогда файлы попадают в
`public/build` после `npm run build`.

**3. Для чего используется функция asset()?**

Она формирует полный URL к файлу в папке `public` с учётом адреса приложения:
`<script src="{{ asset('js/events.js') }}"></script>` превращается в
`http://localhost:8000/js/events.js`. Благодаря этому путь не приходится писать
вручную, и ссылка остаётся правильной при смене домена или переносе проекта.

**4. Как передаются данные из контроллера в Blade?**

Вторым аргументом функции `view()`: либо массивом `view('events.index', ['events' => $events])`,
либо через `compact('events')`. В шаблоне переменная доступна по имени ключа:
`@foreach ($events as $event)`. В проекте так передаются массив мероприятий
(`index`) и объект пагинации вместе со строкой поиска (`database`).

**5. Что такое DOM и как JavaScript получает доступ к HTML-элементам?**

DOM (Document Object Model) — объектная модель документа: представление
HTML-страницы в виде структуры объектов. JavaScript обращается к элементам через
методы поиска: `getElementById()`, `querySelector()` (первый подходящий элемент
по CSS-селектору), `querySelectorAll()` (все подходящие элементы),
`getElementsByClassName()`. Например, `document.querySelector('#pageTitle')`
возвращает элемент заголовка, после чего его можно изменить:
`title.textContent = 'Выберите мероприятие'`.

**6. Для чего нужен метод addEventListener()?**

Он назначает элементу обработчик события: `element.addEventListener('click', function () { ... })`.
Первый аргумент — тип события (`click`, `input`, `submit` и другие), второй —
функция, которая выполнится при его возникновении. При передаче именованной
функции скобки не ставятся: `button.addEventListener('click', handleBuyClick)` —
со скобками функция вызвалась бы сразу, а обработчиком стал бы её результат.
На один элемент можно назначить несколько обработчиков.

**7. Как получить идентификатор из атрибута data-event-id?**

Через свойство `dataset`, где имя атрибута записывается в camelCase:

```javascript
const eventId = card.dataset.eventId;
```

Атрибут `data-event-id="{{ $event['id'] }}"` позволяет передать значение из Blade
в HTML, а `dataset.eventId` — прочитать его в JavaScript. При этом данные из
браузера нельзя считать доверенными: пользователь может изменить HTML и отправить
произвольный идентификатор, поэтому сервер обязан проверять его повторно.

**8. Чем скрытие карточки в JavaScript отличается от удаления записи из базы данных?**

Методы `remove()` и свойство `hidden` меняют только текущий HTML-документ в
браузере. Запись в базе данных остаётся, и после обновления страницы карточка
появится снова, если контроллер по-прежнему её возвращает. Для настоящего
удаления нужно отправить запрос на сервер (например, `DELETE`), проверить права
пользователя и удалить запись через Laravel.

**9. Когда поиск следует выполнять на клиенте, а когда на сервере?**

На клиенте — когда записей немного и они уже загружены на страницу: фильтрация
выполняется мгновенно и без обращений к серверу. На сервере — когда каталог
большой, записи разбиты на страницы или нужны сортировка, фильтры и права
доступа: тогда поиск выполняется SQL-запросом и браузер получает только
подходящие результаты. Клиентский поиск не найдёт записи, которых нет на текущей
странице. Если поиск отправляется на сервер при вводе, применяют задержку
(debounce), чтобы не делать запрос на каждый символ.

**10. Для чего используется CSRF-токен при отправке запросов в Laravel?**

Он подтверждает, что POST-запрос отправлен из интерфейса самого приложения, а не
подделан сторонним сайтом от имени авторизованного пользователя. В Blade токен
выводится в `<meta name="csrf-token" content="{{ csrf_token() }}">` (или через
директиву `@csrf` в форме), а в `fetch()` передаётся заголовком `X-CSRF-TOKEN`.
Защиту от подделки запросов он даёт, но авторизацию не заменяет.

**11. Почему сервер должен самостоятельно проверять доступность билетов и права пользователя?**

Потому что всё, что происходит в браузере, пользователь может изменить: отредактировать
HTML, подставить другой идентификатор, отключить JavaScript или отправить запрос
напрямую. Проверки в браузере нужны только для удобства. Количество свободных
билетов, цена, права на операцию и результат оплаты — это состояние системы,
которое меняется одновременно для многих пользователей, поэтому единственным
источником истины остаётся сервер и база данных. Иначе два человека могли бы
купить один и тот же билет.
